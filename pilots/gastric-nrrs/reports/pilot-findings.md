# Gastric NRRS pilot findings

This log separates defects in the anchor study from problems exposed while
using Paper2Paper. A paper-specific omission is not automatically a reason to
expand the workflow; a workflow change must solve a concrete observed problem.

| ID | Scope | Stage | Severity | Observation | Consequence | Repair/action |
| --- | --- | --- | --- | --- | --- | --- |
| PF-001 | product | intake | high | Poppler could not open the original Unicode path, and PowerShell copying failed because the full filename exceeded the conventional Windows path limit. `hardcoded_paths=false` does not test path portability. | A valid source file can fail before scientific work begins. | Add a path preflight and an auditable short-ASCII staging rule; require a smoke test in the target OS/path environment. |
| PF-002 | workflow | all | high | The workspace had no first-class place to record problems discovered during a Pilot. | Findings could be buried in prose or forgotten. | Add a simple `evidence/issues.tsv` with source, consequence, current repair, workflow action and status. |
| PF-003 | both | data verification | critical | The paper calls cohorts independent, but three GEO-meta component cohorts are later reused as validation. Paper2Paper records cohort overlap but not analysis-role reuse. | A route can pass the current independence check even when validation data participated in feature screening or threshold selection. | Add a cohort-usage ledger and block an `external_validation` claim when the same data were used upstream. |
| PF-004 | both | code verification | high | The eight coefficients are published, but the model remains non-computable without transform orientation, probe aggregation, missing-gene policy and cutoff. | Formula availability can be mistaken for code/model availability. | Add a locked computable-model specification for signature routes and require it before readiness. |
| PF-005 | both | code verification | medium | TIDE, SubMap, IPS and GeneMANIA are mutable external services or resources without a recorded version/query snapshot. | Outputs may change or become unavailable even when local code is stable. | Add service provenance and captured-response requirements to code recovery guidance and analysis contracts. |
| PF-006 | anchor | anchor audit | critical | No code repository or code-availability statement was found. Key package versions, random seed, cutoff and source-table mappings are absent. | Exact model reconstruction and exact figures are not supported. | Treat as paper-specific gaps; reconstruct only bounded analysis steps with donors and tests. |
| PF-007 | anchor | scientific review | critical | Feature screening uses GEO-meta, then its three constituent cohorts are displayed as validation. | Performance is optimistic relative to a fully untouched external validation. | Lower the claim ceiling and prioritize cohorts not involved in development for any new validation. |
| PF-008 | anchor | scientific review | high | Every cohort is standardized separately before applying the score. | The score is cohort-relative and not directly deployable for one new patient. | Evaluate cohort-stratification association only unless a frozen reference transform is created and tested. |
| PF-009 | both | data verification | critical | The GSE62254 Series Matrix contains expression and patient IDs but no OS; OS comes from a separate Nature Communications Supplementary Data 2 workbook, and probe annotation comes from GPL570. | One accession or one candidate row cannot prove that all required fields are obtainable. | Added field-level `data_resources.tsv`; readiness now requires resource coverage of every required field. |
| PF-010 | both | data verification | critical | Expression and outcome were joined across sources. Equal row counts alone would not establish identity. | A silent ordering or ID mismatch could attach survival outcomes to the wrong expression profiles. | Added exact identifier-set, uniqueness and coverage checks and a required `identifier_field` for every resource. |
| PF-011 | product | code verification | high | Dependencies installed successfully in an approved Windows context, but the sandbox context could not read one temporary dependency because of ACL differences. | `install_passed` can be true while the actual execution context remains unusable. | Clarified that install and smoke are distinct and added target-environment path/context evidence to code candidates. |
| PF-012 | workflow | execution | medium | The first real run reached plotting and failed because lifelines expects `ax=`, not `axis=`. Inspection and unit tests that omitted plotting did not catch it. | A plausible reconstructed implementation can fail at the final noninteractive artifact step. | Added a KM artifact test and retained an honest failure summary. The original traceback was not saved, so the record must not claim that it was. |
| PF-013 | both | model verification | high | Mean-probe and highest-variance-probe rules gave Spearman rho 0.972 but changed 14 of 300 high/low assignments. | An omitted probe rule may preserve cohort direction while changing individual classification and estimates. | The new computable-model contract makes mapping and duplicate-feature policy mandatory; both rules are reported as sensitivity. |
| PF-014 | product | data verification | high | The NCBI series matrix had a 2026 Last-Modified date although the accession is from 2015. Public resources can be replaced in place. | Re-running the same URL may silently analyze a different file. | Added version, byte count and per-resource checksum; changed inputs fail closed pending re-audit. |
| PF-015 | product | route selection | critical | The bounded NRRS reproduction is executable, but it asks the same central question as the anchor and is useful here as training rather than a new manuscript route. The old workflow did not separate execution evidence from promotion evidence and user approval. | A technically successful reproduction could be presented to a beginner as a selectable paper direction despite substantive overlap. | Report `execution_ready` separately from `promotion_evidence_complete`; create a formal manuscript only in a user-approved manuscript project. |

## How the findings are used

The issue log records where a problem came from, its type, the current repair,
whether Paper2Paper changed, and the instance status. `resolved` means only
that this Pilot handled the issue; it does not prove a universal rule. PF-006
through PF-008 remain anchor-specific. This Markdown file is the readable
narrative; `evidence/issues.tsv` is the structured local record.
