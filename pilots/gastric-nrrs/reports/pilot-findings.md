# Gastric NRRS pilot findings

This log separates defects in the anchor study from gaps in the reusable
Paper2Paper product. A paper-specific omission is not automatically a reason to
expand the product; a product change requires a reusable control or record.

| PF-001 | product | intake | high | Poppler could not open the original Unicode path, and PowerShell copying failed because the full filename exceeded the conventional Windows path limit. `hardcoded_paths=false` does not test path portability. | A valid source file can fail before scientific work begins. | Add a path preflight and an auditable short-ASCII staging rule; require a smoke test in the target OS/path environment. |
| PF-002 | product | all | high | The workspace has no first-class place to record problems discovered during a pilot and decide whether they are instance-specific or reusable. | Findings are likely to be buried in prose or forgotten. | Add `evidence/issues.tsv` with scope, severity, evidence, impact, disposition and status. |

## Decision rule

The core records each outcome by scope. `resolved_in_pilot` means only this
gastric instance is fixed; `partially_resolved_in_core` means a generic field or
rule exists but does not yet prove the underlying fact; `verified_in_core` means
the reusable control has a regression test. PF-006 through PF-008 remain
anchor-specific. The structured decisions and evidence live in
`evidence/issues.tsv`; this Markdown file is the human-readable narrative, not
the only record.
