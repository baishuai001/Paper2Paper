# CRC-atlas 数据可获得性与 NPJ HCC 替换审计

审计对象：*Single-cell integration and multi-modal profiling reveals phenotypes and spatial organization of neutrophils in colorectal cancer*，*Cancer Cell* 44, 146–165 (2026)，DOI: `10.1016/j.ccell.2025.12.003`。

审计日期：2026-08-08。

## 结论先行

**CRC-atlas 是目前已检查癌种中，最有价值的结直肠癌数据与代码来源之一，但它不是 NPJ HCC 数据的一键替代品。**

它可以实质替代或补强以下角色：

- 大规模、多研究单细胞图谱；
- 正常、腺瘤、原发癌、肝转移、血液和淋巴结等状态/部位的细胞生态比较；
- 髓系细胞程序、细胞互作及部分临床分层；
- 原发 CRC 的细胞分辨空间邻域验证；
- 作者已有的单细胞整合、髓系 cNMF、Xenium、IMC、TCGA/生存分析代码作为可靠代码来源。

它不能直接替代以下角色：

- NPJ HCC 论文以恶性上皮细胞为中心的 cNMF 程序链；CRC-atlas 的现成 cNMF 主要针对髓系细胞，目标论文需要另写恶性上皮程序模块；
- 原发灶到肝转移灶的全转录组空间程序验证；CRC-atlas 自有 Xenium 是 380 基因靶向面板且主要是原发 CRC，不能承载任意新发现的全转录组恶性程序；
- 单一、同质的治疗反应队列；补充表虽有反应信息，但药物、研究和人群高度异质，不能合并成一个笼统“治疗有效/无效”结局；
- NPJ HCC 的 Geneformer 扰动环节；作者仓库没有这一模块，必须使用官方实现并重建数据切分、对照、稳定性与基线测试；
- 任何湿实验、动物实验或类器官实验。CRC-atlas 原文中的这些证据不能被二次计算“复现”，也不应冒充目标论文自己的证据。

因此，**结直肠癌换癌种模仿是可行的候选方向，但当前只能判定为“值得进入真实文件与最小代码试跑”，不能判定为“整条路线已经可执行”。**

## 本次实际检查了什么

本次不是只看论文的数据可用性声明，而是检查了五层证据：

1. 本地论文正文、补充方法和补充表；
2. 作者 GitHub 仓库及其固定提交；
3. CELLxGENE 公开整合对象的文件元数据；
4. Zenodo 发布记录和各归档文件大小；
5. BioImage Archive 的 Xenium/IMC 文件索引，并下载、校验了小型样本表和基因面板。

没有下载约 31 GB 的整合 H5AD，也没有下载约 299 GiB 的全部 Xenium 原始/形态文件；文件体量很大，本轮的任务是确认资源是否真实存在、可取、能提供什么证据，而不是在未确定目标路线前消耗服务器空间。

## 数据可获得性

### 1. 单细胞整合图谱

| 资源 | 已核实内容 | 可获得性 | 适合的角色 | 主要限制 |
|---|---|---|---|---|
| CELLxGENE CRC atlas | 3,790,266 个细胞、28,127 个基因、588 位供者、1,553 个样本、45 个研究；H5AD 约 30.9 GB | 公开、直接下载 | 直接从处理后对象开始做细胞类型、恶性上皮、TME 和跨队列分析 | 单体文件很大；不能在本地内存中一次性载入；需 backed/chunked 读取并冻结子集 |
| 作者网站 H5AD | `final_crc_atlas-adata.h5ad` 约 32.7 GB | 公开、直接下载 | 与作者网站/可视化保持一致的处理后对象 | 同样很大；需要先核对对象版本与 CELLxGENE 版本差异 |
| Zenodo 最终记录 | 9 个归档，包含输入数据、模型、下游分析、差异表达和容器等；合计约 159 GB | 公开 | 精确重跑作者部分流程、取得模型/下游结果和容器 | 不是初学者应一次全部下载的“安装包”；应按模块选择文件 |

这意味着 CRC-atlas 的单细胞数据不是“理论公开”，而是确实存在可下载的处理后对象和重建归档。但“公开”不等于“拿来就能在普通电脑上运行”：必须先为服务器规划存储、内存和子集化策略。

### 2. 补充表中的真实样本与临床信息

本地 `Table S1` 已实际解析并校验，文件大小 `818641` 字节，SHA256 为 `EF58CFC7C00ED9826B8E421767A71D45271F4847155A5E5DDD1620089EE7D920`。它不是只有论文概述，而是包含可以构建分析设计表的患者级和样本级字段：

- 650 位患者、1,670 个样本；患者表 39 列，样本表 64 列；
- 表内可见 49 个 study 标识和 77 个 dataset 标识，而正文概述为 76 个数据集；这可能来自作者对“研究/数据集”或最终对象版本的定义差异，目标分析必须冻结并解释自己的 manifest，不能混用这些总数；
- 样本类型：肿瘤 674、正常 560、肝转移 175、息肉 116、血液 103、淋巴结 42；
- 肝转移样本来自 91 个患者标识、13 个数据集，而不是单一小队列；
- 治疗前状态有记录者 590 人，其中未治疗 487、已治疗 103；
- 治疗反应有记录者 106 人（72 responder、34 non-responder）；
- RECIST 有记录者 78 人（CR 22、PR 30、SD 18、PD 7、NE 1）；
- MSI 状态有记录者 357 人，KRAS/BRAF/APC/TP53 等字段也有不同比例的记录。

这些数字显著改善了 CRC 路线的可行性判断，但不能被误读为“106 人来自同一个治疗试验”。反应病例来自 Qin_2023、Tian_2023、Chen_2024、Li_2023、Wu_2022 等多个数据集，治疗从 FOLFOX/FOLFOXIRI 到抗 PD-1 和联合方案不等。正确用法是：

- 在同一数据集、同一治疗定义内做预先规定的比较；
- 把其他相容队列作为复现/外部验证，而不是把药物不同的患者直接合并；
- 在分析表中保留 `dataset_id`、药物、治疗线次、组织部位、MSI 和取样时间；
- 若无法形成至少一个可解释的治疗问题，就删除“治疗反应”主张，不强行保留 NPJ HCC 的治疗层。

### 3. 空间数据

BioImage Archive `S-BIAD2208` 的文件索引已检查：

- Xenium 全部 2,250 个文件约 321.35 GB（约 299.28 GiB）；
- 其中真正用于第一轮分析的小型子集远小于总归档：19 个 `cell_feature_matrix.h5` 合计约 0.259 GiB，19 个 `cells.parquet` 约 0.078 GiB，19 个 `analysis.zarr.zip` 约 0.032 GiB，外加样本表与面板文件；
- 可先下载约 0.37 GiB 的矩阵、细胞位置和分析对象，而不是下载全部高分辨率形态图和转录本文件；
- IMC 聚合 CSV 约 222 MB，可用于蛋白空间邻域的独立检查；
- 论文补充表列出 15 位 Xenium 患者，涵盖 I–IV 期、MSS/MSI 和部分 KRAS/BRAF 状态；正文报告 37 个组织切片，包含肿瘤核心、边缘和邻近正常区域。

其中 15 位 Xenium 患者里有 11 位填写了对应的单细胞患者标识，因此这不是一个完全独立于图谱发现数据的空间队列。若把这些患者用于程序发现，就不能再把同一患者的空间结果称为独立验证；可把另外 4 位未匹配患者或另一空间数据集用于更严格的外部检查。

关键限制是基因面板。本次下载并校验的 `gene_panel.json` 含 380 个基因，但对许多候选程序覆盖不足：

- `SPP1`、`APOC1`、`HSP90B1`、`HSPA1A/B`、`NDUFA4L2`、`KRT8/18/19`、`CEACAM5` 均不在面板中；
- CRC-atlas 髓系 20 基因程序的覆盖率从 0/20（代谢）到 11/20（T 细胞互作）不等；免疫抑制程序为 6/20、应激程序为 1/20、上皮互作程序为 3/20；
- 因而该 Xenium 数据适合检验细胞身份、免疫邻域和有限的预定义通路，不适合把任意全转录组 cNMF 程序完整投射到空间。

要保留 NPJ HCC 式“恶性程序的空间定位”，应另外解析 GSE225857 或其他全转录组 CRC/CRLM 空间数据，并把 CRC-atlas Xenium 用作**细胞邻域/免疫生态验证**，而不是硬塞进它不能测量的角色。

## 作者代码可获得性与可复用性

作者仓库 `icbi-lab/crc-atlas` 为公开仓库。本次固定检查提交 `82c15ecc2ea36baa0c4cffe8818bf58e21dcfc48`：

- 共 158 个跟踪文件，包括 97 个 Python、17 个 Nextflow、13 个 R 文件以及多个 notebook；
- 有单细胞图谱构建、scANVI/整合、髓系 cNMF、Xenium、IMC、TCGA/生存和下游图表代码；
- 有多个 Conda 环境文件和 Singularity/Nextflow 设计；
- 代码许可证为 BSD 3-Clause Clear，可在保留许可证和归属的前提下复用，但该许可证明确不授予专利许可。

这套代码**质量明显高于只有零散脚本或完全无代码的锚点论文**，值得作为 CRC 目标论文的首要代码来源。不过还没有达到“直接运行即可”的资格：

- README 声称有 `build_atlas` 和 `downstream_analyses` 两条 Nextflow workflow，但仓库实际缺少 `workflows/downstream_analyses.nf` 和它引用的配置；`main.nf` 只接入图谱构建流程；
- 多个配置和启动脚本写死了作者服务器的 `/data/projects/...`、`/data/scratch/...` 路径；
- README 的 Zenodo 状态仍写“coming soon”，而数据实际上已经发布，说明文档与发布状态未完全同步；
- 没有 GitHub Actions 和显式自动化测试；本轮也没有把 31 GB 对象下载后做执行验证；
- 仓库根许可证是 BSD 3-Clause Clear，但 `pyproject.toml` 的项目元数据写有 MIT，复用时应以根许可证为准并保留这一不一致的审计记录；
- 仓库的成熟 cNMF 部分是髓系程序，不是目标论文需要的恶性上皮程序；
- 仓库不包含 Geneformer。

因此代码策略不是抛弃它，也不是假装它已经开箱即用，而是：

1. 固定提交与许可证；
2. 把图谱读取、细胞元数据、髓系程序和空间邻域脚本拆成可调用模块；
3. 删除/参数化硬编码路径，建立项目自己的输入/输出合同；
4. 为恶性上皮细胞补建 cNMF、供者留出、队列留出和种子稳定性代码；
5. 为下游 notebook 增加非交互 runner、小型 fixture 和预期输出检查；
6. Geneformer 使用官方实现，单独做 tokenizer、供者隔离、标签置换和简单基线测试。

补充材料中 Table S1、Table S2 和 Table S4 已用当前表格工具读取；Table S3 因其 Excel 批注作者元数据不满足当前解析器要求而未成功导入。本轮结论没有依赖 Table S3。该问题更像工作簿兼容性而不是数据不公开，但在需要复用 Table S3 内容前仍应以 Excel/修复后的副本重新解析并保存校验记录。

## 一个可执行的 CRC 组装方案

这不是最终论文路线，而是目前最少浪费、最能产生方向证据的试跑顺序：

1. **不从头重建 427 万细胞图谱。** 在服务器上以 backed/chunked 方式读取公开 H5AD，先冻结供者平衡的恶性上皮子集；保留正常、息肉、原发癌和肝转移标签，同时保留数据集、患者、部位、治疗与分子亚型。
2. **恶性程序作为第一决策实验。** 在非负计数上运行小规模 cNMF，检查不同种子、供者留出和数据集留出后程序是否仍存在；若只反映研究平台或某一患者，立即停止“进展程序”主张。
3. **把 CRC-atlas 的髓系与 TME 结果当上下文/代码来源。** 目标论文不重复其“中性粒细胞图谱”中心结论，而检查新得到的恶性程序是否与已有生态状态形成可复现关系。
4. **空间分工。** CRC-atlas Xenium/IMC 用于原发癌细胞邻域；GSE225857 或另一全转录组 CRLM 空间队列用于原发—肝转移程序投射。每个面板先做目标基因覆盖率审计。
5. **临床问题按队列与治疗拆分。** 先选择一个定义清楚、样本量允许的治疗问题；其他治疗队列只在药物机制和终点可比时复现。若不可比，保留生存/分层层而删除治疗反应层。
6. **Geneformer 最后进入。** 只有源/目标细胞状态已经过供者留出验证，才运行官方模型的小型扰动试验；先与差异表达、网络中心性等简单基线比较，再决定是否值得全量 GPU 计算。

这套方案仍然珍惜 NPJ HCC 的“图谱 → 恶性程序 → 生态关系 → 空间验证 → 临床关联 → 计算扰动”框架，但不会照搬它的横断面演化表述、样本伪重复、空间循环验证和无对照扰动等硬伤。

## 目前的停止条件

出现任一情况，就不应继续写“完整换癌种目标论文”，而应缩减 Figure 或更换癌种：

- 恶性上皮细胞无法在供者/数据集留出后形成稳定程序；
- 正常、息肉、原发和肝转移完全与数据集/平台绑定，且找不到桥接队列；
- 空间面板不含目标程序的足够基因，且找不到全转录组替代；
- 选择的治疗队列没有清楚的药物、时间点和反应定义；
- 最近论文已经用相同疾病状态、数据、分析顺序和中心关系形成了实质相同结论；
- 最小真实数据试跑无法在目标服务器的存储、内存和 GPU 条件下稳定完成。

## 当前决定

**CRC 路线继续，进入“文件级预检 + 最小真实代码试跑”，但不晋升为已经选定的目标论文。**

下一步只需要取得决定性证据，不需要先下载全部 159–300 GB 资源：

- 服务器存储/内存检查；
- 31 GB H5AD 的 backed 读取与供者平衡恶性子集导出；
- GSE225857 文件结构、患者匹配和空间角色解析；
- 一个小型恶性 cNMF 稳定性试跑；
- 一个治疗队列的药物/反应合同核查；
- 一个 Geneformer tokenizer/扰动 smoke test；
- 围绕拟定中心问题完成最近论文逐项重复性审计。
