# NPJ HCC 锚点文献换癌种总体评估

审计对象：*Large-scale single-cell analysis and in silico perturbation reveal dynamic evolution of HCC: from initiation to therapeutic targeting*，DOI：`10.1038/s41698-026-01307-2`。

审计日期：2026-08-08。

## 一、直接回答：能否换癌种模仿

**能。** NPJ HCC 锚点文献的主要价值是一套可迁移的“问题—证据—分析—Figure”框架，而不是 HCC、HSP90B1 或某一组固定细胞标签。把癌种换成结直肠癌、胃癌、前列腺癌等，本身就是 Paper2Paper 允许且应认真考虑的简单模仿方式。

但需要区分四个层次：

1. **框架层面：可以迁移。** 多队列单细胞图谱、恶性程序、免疫/基质生态、空间定位、临床投射和计算扰动的证据顺序，在其他癌种仍然成立。
2. **数据层面：必须逐角色替换。** 不是找到一个“大型单细胞数据”就完成替换，而是要为每个主要 Figure 找到能承担同一科学角色的数据；缺失的角色可以补数据，也可以诚实删减 Figure。
3. **代码层面：可以重建，但尚未完成。** 锚点作者代码不可直接获得，必须组合官方实现、目标癌种作者代码和同类论文的可靠模块，并在真实目标数据上运行。
4. **论文层面：目前尚未成立。** CRC 是最值得进入真实小试跑的候选，但还没有产生恶性程序、空间复现、临床结果或扰动结果，因此现在不能声称“已选定结直肠癌目标论文”。

所以当前准确结论是：

> **NPJ HCC 可以换癌种模仿；CRC 已达到“有充分资源进入决定性预实验”，但还没有达到“完整目标论文路线可执行”。**

这不是设置 PaperRoute 式创新性门槛。简单替换癌种、细胞、状态、结局或分析模块都可以接受。唯一不能接受的是：数据取不到、代码不能可靠运行、逻辑不成立，或者与已经发表的论文实质重复。

## 二、要模仿的到底是什么

NPJ HCC 的可利用框架可以概括为六个连续环节：

1. **建立疾病状态图谱**：整合正常/邻近、早期、原发、进展或转移状态的多个单细胞队列。
2. **提取恶性细胞程序**：识别恶性细胞，使用 CNV、NMF/cNMF 等方法得到反复出现的表达程序，而不是只列细胞簇 marker。
3. **连接肿瘤生态**：分析恶性程序与髓系、淋巴、内皮、成纤维状态及细胞互作的关系。
4. **进行空间验证**：把预先冻结的程序或细胞状态投射到多个患者/切片，检验生态位和邻域关系。
5. **连接临床或治疗结局**：在独立患者队列中检验生存、治疗反应或其他明确临床结局。
6. **计算扰动与候选靶点排序**：用 Geneformer 或其他模型提出可能改变细胞状态的候选，并通过稳定性、空模型、简单基线和正交证据限制解释。

目标论文可以有三种合法形态：

- **完整框架模仿**：六个环节均由真实数据和可靠代码支持；
- **缩减框架模仿**：保留锚点的主要逻辑，但删除确实没有数据支撑的治疗、空间或扰动环节；
- **模块化模仿**：只利用锚点中一段高价值框架，例如“恶性程序—生态关系—空间复现”，形成更小、更适合初学者的论文。

不要求为了“更创新”而强行增加环节，也不要求保留锚点的所有 Figure。Figure 数量应服从数据和中心问题。

## 三、锚点文献硬伤必须怎样修复

发现硬伤的目的不是否定锚点，而是让目标论文避免重复这些问题。

| 锚点问题 | 对目标论文的影响 | 必须采用的修复 |
|---|---|---|
| 183 个原始样本如何变成 115 个保留样本没有完整 ID 清单 | 无法精确复现样本选择 | 冻结患者—样本—数据集 manifest，逐条记录纳入、排除和理由 |
| 横断面不同患者/队列被表述成 initiation/evolution | 不能证明时间演化或谱系转换 | 使用“状态差异、状态序列、关联”表述；除非有纵向或谱系证据，不写动态演化 |
| PVTT、MLN 等关键组患者极少 | 总细胞数掩盖患者数不足 | 决定性比较按患者计数并设置每组最低患者数；细胞不能替代患者 |
| 细胞可能被当作独立重复 | P 值虚假变小 | 患者/供者作为统计单位，使用 pseudobulk、混合模型或患者层置换 |
| cNMF 输入为处理过的 Harmony 残差且有裁剪，细节不足 | 非负输入与生物解释不清 | 使用原始/非负计数或明确的非负表达矩阵；保存输入合同和稳定性结果 |
| 跨队列状态可能与数据集/平台完全重合 | 所谓进展程序可能只是批次差异 | 构建患者×队列×状态×平台表，设置桥接队列、留一数据集验证和敏感性分析 |
| 同一空间区域可能既用于发现又用于验证 | 形成循环论证 | 冻结程序后再投射；按患者/切片分离发现和验证；使用空间空模型和独立复现 |
| Geneformer 的数据切分、seed、checkpoint、空模型和代码缺失 | 排名难以复核，不能说明因果 | 固定模型和 token 字典；患者隔离；多 seed；标签置换；与简单差异/网络基线比较 |
| HSP90B1 等候选缺乏肿瘤选择性及实验验证 | 不能直接称为治疗靶点 | 只称“计算候选”；检查正常组织、细胞类型特异性和正交数据；没有实验就限制结论 |

这些修复不改变“模仿锚点”的性质，反而是对锚点框架更严谨的利用。

## 四、CRC-atlas 能替换 NPJ HCC 的哪些部分

用户提供的 CRC-atlas 使 CRC 从“只有若干 GEO 候选”升级为“已有完整患者/样本表、公开处理后对象、作者代码和空间资源的真实候选”。

### 已核实的资源

- CELLxGENE 处理后对象约 30.9 GB，含 3,790,266 个细胞、588 位供者、1,553 个样本；
- 本地 Table S1 已解析：650 位患者、1,670 个样本，包括正常、息肉、原发癌、肝转移、血液和淋巴结；
- 175 个肝转移样本对应 91 个患者标识和 13 个数据集；
- 106 位患者有 response，78 位有 RECIST，但来自不同研究和药物；
- BioImage Archive 提供 Xenium 和 IMC；全量约 299 GiB，首轮矩阵/位置/分析对象约 0.37 GiB；
- 作者 GitHub 含图谱构建、髓系 cNMF、Xenium、IMC 和 TCGA 生存代码。

### Figure 角色替换判断

| 锚点角色 | CRC-atlas 单独能否替代 | 仍需补什么 |
|---|---|---|
| 多队列单细胞图谱 | 能 | 不再把“建立 CRC 大图谱”当新结果，而把它作为目标分析基础 |
| 恶性细胞程序 | 部分能 | 从 H5AD 提取恶性上皮细胞；补 malignancy 判定、恶性 cNMF、患者/数据集留出 |
| 髓系和 TME 生态 | 能 | 避免重复原文中性粒细胞主线；只用于检验目标恶性程序与生态关系 |
| 细胞互作 | 能重建 | 患者层统计、空间邻近和独立数据复现；不写成因果 |
| 原发 CRC 空间邻域 | 能 | 先做 380 基因面板覆盖率审计；11/15 Xenium 患者与 scRNA 有关联，不能全部称独立验证 |
| 原发—肝转移全转录组空间验证 | 不能 | 解析 GSE225857 或其他 CRC/CRLM 全转录组空间数据 |
| 临床/治疗 | 部分能 | 选择一个药物、时间点和终点相对一致的队列；不能合并所有 response |
| Geneformer | 不能 | 使用官方实现，补患者隔离、seed、空模型和简单基线 |

### CRC 的当前状态

CRC 不是“已经选定的目标论文”，而是当前证据最充分的**决定性预实验对象**。它需要先回答：

1. 恶性程序能否跨患者和数据集稳定出现；
2. 正常/息肉/原发/肝转移差异是否只是队列和平台差异；
3. 空间数据是否真正测得到这些程序；
4. 能否找到一个定义清楚的治疗问题；
5. 最近论文是否已用相同数据和证据顺序回答了相同中心关系。

只有这些问题得到真实结果，才讨论目标论文标题和主线。

## 五、其他癌种的当前判断

其他癌种不是只检索到一个结果。此前文档只展示了每个癌种的代表性资源，容易造成“每个癌种只查了一篇”的误解。现已在 `reports/other-cancer-data-screen.md` 中扩展为多资源清单，并标明检索、元数据、文件解析和运行等级。

当前概要如下：

| 癌种 | 资源链状况 | 当前用途判断 |
|---|---|---|
| 前列腺癌 | 有 2026 harmonized scRNA atlas、GSE278936 空间/治疗时间线、多个公开代码仓库 | 下一轮文件级审计优先候选；不能重复 club-like 上皮—髓系主线 |
| PDAC | 有 GSE272362、GSE274557、GSE277782 及多个原发—转移空间代码仓库 | 数据和代码很强，但 2024–2026 已有多篇转移空间论文；适合作为数据/代码来源并做严格重复性审计 |
| 乳腺癌 | 有 GSE176078、空间图谱、健康参考和 2026 同步 DCIS/IBC 队列 | 资源易用，但原位—浸润进展已经被直接发表；需另找治疗或转移问题 |
| HGSC | 有 Zenodo、Single Cell Portal、GSE211956、GSE298031、空间/CRISPR 代码 | 高质量空间和扰动代码来源；完整框架已有近似论文，需避免重复 |
| LUAD | 有正常/原发/多部位转移 scRNA、HRA001238 空间及多篇早期—侵袭空间队列 | 角色丰富，但数据分散且部分受控；队列—状态混杂和近邻论文多 |
| ICC | 有 GSE138709、GSE151530、多队列整合和 9 位患者 leading-edge scRNA/空间代码 | 简单换癌种仍可认真考虑，但每组患者数、空间公开性和独立临床层仍需文件审计 |
| ccRCC、黑色素瘤、BCC | 有治疗前后、应答/耐药和纵向空间资源 | 更适合补治疗模块；是否能承担完整锚点框架尚未证明 |

## 六、什么情况下可以形成目标论文

换癌种路线不需要“最创新”，但至少要同时满足以下条件：

1. **问题成立**：目标癌种确实存在可由该框架回答的具体问题；
2. **数据够用**：每个主要结论有真实可取得的数据，决定性分组有足够患者；
3. **代码可靠**：作者代码、官方模块或同类论文代码经过固定版本、路径适配和真实 smoke test；
4. **Figure 能闭环**：发现、复现、空间、临床/扰动之间围绕同一中心关系，而不是拼图；
5. **硬伤已修复**：不复制锚点的横断面演化、伪重复、循环验证和无对照扰动；
6. **不实质重复**：可以是简单模仿，但不能使用近乎相同的数据、对象、分析顺序和中心结论重新发表一次；
7. **初学者可完成**：下载、计算、调试和审查负担在实际时间与服务器条件内。

“不实质重复”是基本发表边界，不是额外的高创新门槛。若简单替换能够形成一篇科学上成立、数据代码可靠且未被完全发表的论文，就应优先于复杂但不可执行的路线。

## 七、当前决定与下一步

当前不选择最终癌种，也不晋升任何目标论文路线。

下一步先用 CRC 完成一个最小但真实的方向判定：

1. 检查服务器存储和内存；
2. backed 读取 CRC-atlas H5AD，导出供者平衡的恶性上皮子集；
3. 生成患者×数据集×状态×部位×治疗设计表；
4. 解析 GSE225857 的患者、单细胞、空间和治疗对应关系；
5. 运行小规模恶性 cNMF，检查 seed、患者留出和数据集留出；
6. 对候选程序做空间面板覆盖率检查；
7. 选择一个治疗定义清楚的子队列；
8. 最后才做 Geneformer smoke test 和最近论文中心关系审计。

如果 CRC 失败，失败原因会直接帮助比较前列腺癌、PDAC、胃癌、ICC 等候选，而不是毫无依据地“彻底换方向”。

## 八、Paper2Paper 在这件事上的能力边界

Paper2Paper 目前已经能组织锚点框架、Figure 角色、数据/代码候选、硬伤修复、重复性风险和最小实验，但还没有完成任何一个“多队列单细胞 + 空间 + foundation model”的换癌种真实闭环。

因此它现在能支持**方向审计和预实验设计**，不能声称已经具备自动产出这类目标论文的能力。具体缺口、补法和验收条件见 `reports/paper2paper-gap-assessment.md`。
