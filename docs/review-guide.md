# 初学者审查指南

Paper2Paper的记录是为了让用户能够检查AI，而不是让用户阅读更多术语。

首先确认报告说的是哪一层：结构和合同校验、单元测试、真实数据运行，还是科学审查。
其中任意一层通过，都不能自动代替另外三层。

## 审查候选路线

逐条问：

1. 我能用一句话复述问题吗？
2. 这是最终稿件候选、训练复现，还是仅用于支撑其他路线？
3. 它只是 `execution_ready`，还是已完成晋升证据审查并获得用户批准？正式稿件是否在独立的 manuscript project 中建立？
4. 相比锚点到底改了什么？
5. 比较、结局和统计单位是否明确？
6. 什么结果会使路线失败？
7. 是否有更简单的路线能回答同一问题？

## 审查数据

- 报告的是患者数还是细胞数？
- 必需字段是否在实际下载文件中出现？
- 每个字段来自哪个具体文件，跨来源ID是否100%核对？
- discovery和validation是否共享患者？
- validation是否曾参与特征筛选、调参或cutoff，即使患者不与训练集重叠？
- 公开链接是否真正可下载？
- 数据缺失会删除哪个claim或Figure？

## 审查代码

- 代码对应哪个具体模块？
- 版本、许可、环境和入口是否固定？
- `license`是否是真实许可证或明确授权，而不是“未知”“未选择”或“仅内部使用”等占位语？
- 是否在目标环境运行过，而不是只看过README？
- 是否在实际OS、用户权限和含空格/Unicode的路径下运行过？
- smoke test使用了什么真实输入，生成了什么输出？
- AI重建部分有哪些donor和测试？
- signature能否仅凭锁定合同为一个新输入稳定重算，而不是依赖未记录的队列统计量？

## 审查Figure

- 每幅主图服务哪个claim？
- 数据和代码依赖是否已经验证？
- source table和验收条件是什么？
- 删除这幅图是否影响中心论文故事？

## 审查路线选择

优先选择：

- 数据真实可取；
- 代码已运行或仅需有限重建；
- 最低主图完整；
- 科学设计清楚；
- 初学者能理解并复查；
- 非实质重复发表。

不要因为期刊档次想象、热门术语或分析数量更多而选择路线。

## 用户必须亲自批准

- 正式路线；
- 中心claim和claim ceiling；
- 放弃不可逆数据机会；
- 看过结果后的reroute；
- 最终稿件和发布。
