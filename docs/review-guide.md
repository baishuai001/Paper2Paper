# 初学者审查指南

Paper2Paper 的记录是为了让用户能够检查 AI，而不是让用户阅读更多术语，更不是把资料搜集、代码核查和路线判断交还给初学者。AI 必须先完成调查、作出明确判断并解释依据；下列表格和问题是可追溯的审查线索，用户可以按风险抽查，而不必逐项代替 AI 工作。

首先确认报告说的是哪一层：结构和合同校验、单元测试、真实数据运行，还是科学审查。
其中任意一层通过，都不能自动代替另外三层。

## 审查候选路线

逐条问：

1. 我能用一句话复述问题吗？
2. 这是最终稿件候选、训练复现，还是仅用于支撑其他路线？
3. 它只是 `execution_ready`，还是已完成晋升证据审查并获得用户批准？正式稿件是否在独立的 manuscript project 中建立？
4. 相比锚点到底改了什么？
5. 比较、结局和统计单位是否明确？
6. 什么结果会使路线失败？
7. 是否有更简单的路线能回答同一问题？

## 审查数据

- 报告的是患者数还是细胞数？
- 必需字段是否在实际下载文件中出现？
- 每个字段来自哪个具体文件，跨来源ID是否100%核对？
- discovery和validation是否共享患者？
- validation是否曾参与特征筛选、调参或cutoff，即使患者不与训练集重叠？
- 公开链接是否真正可下载？
- 数据缺失会删除哪个claim或Figure？

## 审查代码

- 代码对应哪个具体模块？
- 版本、许可、环境和入口是否固定？
- `license`是否是真实许可证或明确授权，而不是“未知”“未选择”或“仅内部使用”等占位语？
- 是否在目标环境运行过，而不是只看过README？
- 是否在实际OS、用户权限和含空格/Unicode的路径下运行过？
- smoke test使用了什么真实输入，生成了什么输出？
- AI重建部分有哪些donor和测试？
- signature能否仅凭锁定合同为一个新输入稳定重算，而不是依赖未记录的队列统计量？

## 审查Figure

- 每幅主图服务哪个claim？
- 数据和代码依赖是否已经验证？
- source table和验收条件是什么？
- 删除这幅图是否影响中心论文故事？

## 审查路线选择

AI 必须对进入短名单的路线完成可比的最低预检，并报告以下维度：

- 数据真实可取；
- 代码已有可靠实现，或存在可测试、可追溯的同类文献/方法/官方 donor 补足方案；
- 最低主图能够形成证据闭环；
- 科学设计清楚；
- 初学者能理解并复查；
- 与最接近已发表工作的具体重合和区别。

这些维度需要共同判断，不是固定的“代码第一”排序，也不使用隐藏加权分数。复杂路线不天然优于简单路线，现成代码也不能挽救错误的科学设计；反过来，锚点代码缺失不等于路线失败，只要能从同类文献、方法论文或官方实现补足并通过合同、测试和真实输入验证。

实质重复判断只能针对具体路线：如果某一疾病—对象—关系—结局—证据链的组合已经被充分发表，则停止或修改该组合；不得据此淘汰所有 signature、泛癌、marker 替换或其他简单模仿方式。

不要因为期刊档次想象、热门术语或分析数量更多而选择路线。

AI 的交付顺序应当是：先给出当前首选和备选，再给出依据、反对理由、不确定性和会改变判断的新证据，最后附上明细供抽查。若最低证据尚不可比，AI 应继续补证，而不是让用户从未核实的候选清单中猜选。

## 用户必须亲自批准

- 正式路线；
- 中心claim和claim ceiling；
- 放弃不可逆数据机会；
- 看过结果后的reroute；
- 最终稿件和发布。
