# 真实文献驱动的双循环

## 为什么要有两个循环

只做当前论文而不记录反复出现的错误，会不断重踩数据、代码和统计陷阱；每遇到问题就扩建平台，又会让论文永远无法开始。Paper2Paper 因此保留主循环和次循环，但明确规定论文优先。

## 主循环：从锚点文献到目标论文

### 1. 完整审计锚点框架

逐 Figure 还原科学问题、中心关系、统计单位、数据/队列角色、证据顺序、分析步骤、输出、claim 和不可复现边界。把锚点当作一套值得珍惜和利用的框架，而不是等待挑错的对象。

每项硬伤同时建立修复设计：受影响 Figure/claim、未受影响框架、目标论文中的修复、验证/推翻证据、剩余风险和 claim ceiling。

### 2. 生成目标论文候选

候选轴来自该锚点自身，而不是固定菜单。对文献特有的对象、疾病、关系、尺度、结局、证据顺序、数据角色、分析步骤和 Figure 结构比较保留、修复、替换、扩展或删除。

简单与复杂路线具有同等候选资格。近邻论文既用于判断具体重复，也用于提供数据、代码、方法和 Figure donor。AI 要形成可比较路线并给出明确判断，不能用创新等级或隐藏分数排序。

### 3. 低成本可得性预检

先写清每条路线最低需要什么数据、字段、代码、输出和 Figure，再检查：

- 文件是否真实可下载、解析和连接；
- 统计单位和队列用途是否正确；
- 锚点代码是否合格，缺失时有哪些可靠 donor 或重建依据；
- 许可、版本、环境和非交互入口是否明确；
- 最近工作是否已经发表同一具体研究组合。

### 4. 最小真实运行

选择最能尽早推翻路线的关键环节，在真实环境和真实文件上运行。保留 manifest、命令、环境、日志、失败/成功 artifact、代表性 source table 或 Figure 片段，并说明结果怎样改变路线。

### 5. AI 建议与用户决定

AI 先提交首选、备选、依据、反对理由、不确定性和会改变建议的新证据。用户决定建立目标论文、修改后再试、保留训练或停止。

### 6. 正式论文生产

获批路线在独立 manuscript project 中冻结规范、执行完整 Figure 链、解释结果并写作。阴性结果可以降低、修改或停止 claim，但不能被覆盖。

## 次循环：真实文献反过来改进 Paper2Paper

### 1. 记录具体问题

`issues.tsv` 记录问题来自锚点、Pilot 执行、两者共同或科学结果，并写明观察、证据、后果、当前论文修复、是否需要 workflow 修改和状态。

### 2. 先修当前论文

任何 workflow 建议都不能代替当前实例处理。先回答数据、Figure 和中心 claim 受到什么影响，能否修复、替换、降级或停止，以及修复后需要哪个新运行。

### 3. 判断是否值得修改 workflow

只有同时满足以下条件才改 Paper2Paper：

- 问题真实发生，而非假想；
- 会造成错误数据、错误结论、不可复现或明显重复劳动；
- 能形成清楚、有限、可检查的规则或实现；
- 修改成本小于对当前和近期论文的实际价值。

论文特有细节留在 Pilot；没有可检查控制的建议留作说明，不扩建产品。

### 4. 最小修改并复验

只修改解决问题所需的文档、schema、代码或测试。随后用发现问题的同一真实 Pilot 重新校验或运行；如果改变科学结果，保留新旧结果和原因。

### 5. 回到主循环

复验通过后立即继续当前论文。是否以后可用于其他文献，要在那些文献真正使用时重新核对输入、方法和科学边界；不提前建立成熟度等级。

## 防止循环确认

- 单元测试证明规则被实现，不证明它适用于所有真实论文。
- 一个 Pilot 通过不证明整个 workflow 可靠。
- expected result 不能只由同一实现刚生成的结果自证。
- 用于筛选、拟合、调参或 cutoff 的队列不能再称为独立验证。
- 最近发表检索不能只搜索支持预期路线的词。
- workflow 修改不能以“让来源 Pilot 通过”为唯一目标；仍需检查科学边界。

## 何时停止次循环

当获批路线已有可取得数据、可靠代码、Figure 闭环、明确 claim ceiling 和非重复依据时，停止产品建设，转入论文分析和写作。只有真实论文出现新的阻断问题时，才重新进入次循环。

双循环是否有效，不看规则和测试数量，而看：更早发现不可行路线、减少误判、缩短得到真实结果的时间，并让至少一条路线持续推进到 Figure 和稿件。
