# 真实文献驱动的学习循环

## 为什么需要双循环

只分析论文而不积累可复用经验，会反复寻找同类数据、重写同类代码并重复踩坑。反过来，如果每遇到一个问题就扩建 Paper2Paper，项目会被平台工程拖住，最终没有论文产出。

解决办法不是把两件事混在一起，而是规定主次：

- **论文循环是主循环**：珍惜并利用锚点文献的独特分析框架，让当前真实文献的分析越来越完整，并把合格路线推进成目标论文；
- **产品学习循环是次循环**：只吸收能够可靠减少以后错误、时间或审查负担的发现。

## 主循环：从锚点到正式论文

### 1. 锚点审计

先把锚点文献当作一套需要理解和利用的分析框架，而不是一组等待挑错的结果。逐 Figure 拆出：

- 科学问题和中心关系；
- 疾病、人群和统计单位；
- 数据、metadata 和不可公开部分；
- 方法、代码和未报告作者选择；
- 输出、claim 和 claim ceiling；
- 可保留、修复、替换、扩展、删除和阻断的模块。

框架要素随论文类型变化，不受上述列举限制。对于每项硬伤，必须建立修复卡：

- 问题证据和未修复时失效的 Figure/claim；
- 未受影响、仍值得保留的框架与模块；
- 数据替代、统计修正、代码重建、验证重排或 claim 降级方案；
- 方案如何落实到目标论文；
- 能够验证或推翻修复的最小证据；
- 修复后的剩余风险和 claim ceiling。

硬伤默认触发修复设计，不默认触发换锚点。只有中心问题不可证伪、所有科学上合理的修复或等价替代均失败，或修复后已失去锚点的中心逻辑时，才把整套框架标为停止/重定向；局部可借鉴模块仍须保留。

### 2. 路线组合

不存在适用于所有论文的固定替换清单。先根据当前文献的研究任务、对象与尺度、中心关系、背景/干预、主要结局、数据和队列角色、证据顺序、方法模块及 Figure 叙事生成改变轴；遇到其他类型论文时继续增加该论文特有的要素。然后对每个要素选择保留、修复、替换、扩展或删除，并形成有边界的组合。

原样复现、marker/基因集、细胞、癌种、泛癌、signature、证据顺序调整、代码 donor 替换和设计修复都只是可调用的例子，而不是必选菜单。每条实际候选路线必须说明：

- 保留和改变什么；
- 一句话问题、比较、主要结局和 falsifier；
- 最低数据、代码和 Figure；
- 初学者负担、时间、最大风险和停止条件；
- 最近发表和可能的实质重复。

### 3. 可得性预检

先写数据和代码合同，再搜索候选。预检只回答低成本问题：

- 必需文件是否真实存在并可访问；
- 必需字段是否出现在文件中；
- 患者/样本 ID 是否能够连接；
- 代码是否有许可、固定版本和非交互入口；
- 目标环境是否可能运行；
- 候选路线是否已经被同类论文实质发表。

### 4. 最小真实运行

选择最容易推翻路线的关键环节，用真实文件和真实环境完成小闭环。它至少保留：

- 输入 manifest；
- 命令、环境、版本和日志；
- 失败或成功 artifact；
- 一个代表性 source table 或 Figure 片段；
- 对主张和下一步的影响。

最小运行不是提前完成整篇论文。它的价值是尽早停止不可行路线，或确认高成本投入有依据。

### 5. 用户决定与正式项目

AI 提交可比较的选择包和建议，用户决定：

- 晋升某条路线到 `manuscript-projects/`；
- 保留为备份或训练案例；
- 修改问题、数据或模块后再试；
- 停止。

正式项目建立后冻结分析规范、运行完整 Figure 证据链，并让 claim 随结果提高、降低或删除。

## 次循环：从 Pilot finding 到可复用能力

### 第一步：分类

| Finding 类型 | 例子 | 默认处理位置 |
| --- | --- | --- |
| 锚点论文缺陷 | cutoff、代码或患者映射未公开 | 当前 Pilot 的复现边界与 claim ceiling |
| Pilot 实现缺陷 | 绘图参数错误、某解析器路径失败 | 当前 Pilot 代码和测试 |
| Module 缺陷 | 所有同类微阵列 signature 都需显式多探针规则 | 对应 module 合同和测试 |
| Core 缺陷 | 运行成功与论文资格未分开 | core schema/校验/纪律 |
| 科学结果 | 换癌种后 marker 无患者级关联 | 保留阴性结果并修改/停止路线 |

分类可以在新证据出现后调整，但必须留下变更理由。科学结果不能为了维护 workflow 的“成功率”而改写成实现故障。

### 第二步：先处理当前实例

每个 finding 先回答：

- 当前文献受到什么影响；
- 是否阻断数据、Figure 或中心 claim；
- 锚点文献的哪些框架仍然有效和值得利用；
- 当前 Pilot 能否修复、降低主张、替换数据/代码/模块或重排验证；
- 修复如何进入目标论文，如何验证，剩余风险是什么；
- 修复后新增哪个 run 和测试。

不能只提交一条核心建议而让当前真实文献保持错误状态。

### 第三步：提出晋升，而不是自动晋升

晋升建议必须具备：

- 清楚、可复现的观察；
- 对论文或执行的实际后果；
- 明确目标层：module 或 core；
- 可机械检查的合同或测试；
- 适用与不适用范围；
- 预计影响的既有能力和 Pilot；
- 实现成本与对当前论文的价值。

若问题只属于某篇论文、没有可测试控制，或预计实现成本超过论文价值，则保留在 Pilot 或待办，不进入产品核心。

### 第四步：成熟度晋升

Promotion 的成熟度为：

| 成熟度 | 含义 |
| --- | --- |
| `observed` | 在真实案例中发现，尚未形成合格晋升证据 |
| `provisional` | 已有合格案例、反例测试和审查人，主要由来源 Pilot 支持 |
| `confirmed` | 不同 Pilot、锚点和数据集的 reference/transfer 真实案例共同支持 |
| `rejected` | 证据不足、分类错误或不值得进入目标层 |
| `deprecated` | 已确认规则后来被证据否定、范围收窄或替代 |

Module release 使用另一组成熟度：`draft`、`unit_verified`、`reference_verified` 和 `transfer_verified`。Promotion 是否被确认与模块实现是否通过真实数据是两件事，不能用一个状态相互替代。

普通规则采用“两次命中”原则。高风险安全规则可以第一次出现就以 `risk_class=safety`、`maturity=provisional` 暂时强制，例如患者身份连接、开发/验证泄漏、隐私、许可和 checksum；此时仍必须说明尚未完成独立迁移验证。

### 第五步：选择性回归和旧 Pilot 更新

变更进入 module/core 后：

1. 从 regression registry 找到受影响的 capability 和 Pilot；
2. 运行结构/单元测试；
3. 对必要案例执行新的真实 run，而不是覆盖旧运行；
4. 比较新旧结果；
5. 更新该 Pilot 的路线、限制和决定；
6. 如果迁移成功，更新成熟度；失败同样登记为 failure case。

核心 schema 改动不应要求所有测序项目重新下载；探针聚合规则也不应触发空间转录组 Pilot。影响范围必须由合同和 registry 决定。

## 能力矩阵如何随新文献增长

引入新文献前先说明它承担哪种作用：

- **扩展覆盖面**：增加尚未覆盖的模态、统计单位或分析能力；
- **迁移验证**：作为既有 provisional 能力的第二个独立案例；
- **失败边界**：检验能力在哪些条件下不能复用；
- **正式路线候选**：直接服务一篇可能产出的论文。

每篇文献可以同时承担多项作用，但必须分别登记。选择新文献不以“数量越多越好”为目标；如果它既不推进论文，也不填补能力证据，就不应优先投入。

## 防止循环确认

### 数据循环

- 用于 marker/特征筛选、模型拟合、参数选择或 cutoff 的队列不能再称为独立验证；
- 不同 accession 不自动等于不同患者；
- 用同一结局生成候选再用同一结局证明候选有效，必须明确为开发或探索分析。

### 代码循环

- “程序能够运行”不能由程序自己的成功消息证明；
- expected results 不能只来自同一实现刚生成的数值，需结合冻结数据版本、独立公式、方法依据、科学不变量或第二实现；
- 一个图看起来合理不能替代行数、方向、ID、统计单位和参数测试。

### 产品规则循环

- 来源 Pilot 可以发现规则并提供第一例，但不能同时充当唯一的跨 Pilot 验证；
- 合成单元测试证明规则被实现，不证明规则适用于所有真实论文；
- 新规则如果使来源 Pilot“通过”，仍要检查它是否只是围绕该 Pilot 过拟合。

### 论文方向循环

- 最近发表检索不能只搜索预期支持路线的关键词；
- “与锚点不同”不等于“没有其他论文已经发表”；
- 路线的可区分点必须来自实际疾病、对象、关系、结局、数据或证据链差异，而不是换标题。

## 何时停止产品循环

以下条件同时满足时，停止为了通用化而扩建 Paper2Paper，转入正式论文生产：

- 用户已经批准一条正式路线；
- 必需数据已经实际获得并通过身份/字段审计；
- 必需模块在目标环境可靠运行；
- 最低 Figure 证据链可以重建；
- claim ceiling 与停止条件清楚；
- 最近发表没有发现实质重复；
- 剩余工作主要是完整分析、解释和写作。

只有正式论文暴露新的阻断问题，或新的 Pilot 提供足够晋升证据时，才重新进入产品循环。

## 如何判断正向循环是否成立

Paper2Paper 变好不以规则数量衡量，而以这些结果衡量：

- 新文献到第一个真实结果所需时间缩短；
- 数据和代码可用性误判减少；
- 失败路线更早被停止；
- 可复用模块在兼容文献中稳定迁移；
- 旧 Pilot 因新规则获得更准确的边界，而不是被强行宣布“通过”；
- 用户能看懂每个判断的事实、依据、不确定性和下一步；
- 至少一条真实路线持续推进到 Figure 和稿件，而不是长期停留在平台建设。
