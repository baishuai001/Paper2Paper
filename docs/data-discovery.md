# 数据发现与验证

数据工作回答两个不同问题：**在哪里可能有数据**，以及**这些数据是否真的能支撑某条路线**。

## 先写数据需求合同

每条路线先在 `data_requirements.tsv` 中定义：

- 证据角色：discovery、external validation、single-cell localization、spatial validation等；
- 疾病、组织、阶段、治疗和取样场景；
- 模态和数据层级；
- 真正支持claim的生物学单位；
- 比较或主要结局；
- 不可缺少的metadata；
- 最低受试者数；
- 可接受的访问条件；
- 是否必须独立于其他队列。

需求不明确时不得开始“搜数据”，否则很容易围绕偶然找到的文件改变问题。

## 按模态建立搜索矩阵

可使用的来源类别包括：

| 数据需求 | 首选来源类别 | 必查内容 |
| --- | --- | --- |
| bulk表达和临床结局 | 癌症基因组门户、GEO/BioStudies、论文补充数据 | 患者ID、结局定义、随访、平台、表达层级 |
| 单细胞 | GEO/SRA、CELLxGENE、单细胞门户、论文对象仓库 | donor/sample ID、组织、治疗、counts、注释来源 |
| 空间转录组 | GEO/BioStudies、论文数据门户、通用对象仓库 | 患者和切片ID、坐标、区域、panel或全转录组覆盖 |
| 治疗反应 | 临床研究数据仓库、治疗队列论文和补充材料 | 治疗方案、时间点、反应标准、基线样本 |
| 蛋白/流式/影像 | 对应专业仓库和论文补充材料 | 原始文件、抗体或panel、批次、患者映射 |

数据库会变化，因此项目必须保存实际访问的来源、检索式和日期，而不是只保存本手册中的名称。

## 构建检索式

每次搜索至少组合：

```text
疾病同义词
+ 组织/转移部位
+ 模态
+ 核心对象或细胞
+ 结局/治疗/阶段
+ data/accession/single cell/spatial 等数据词
```

同一需求使用宽检索和窄检索。零命中也写入 `search_log.tsv`，避免下一个审查者重复劳动或误以为没有搜索。

## 候选预筛

候选写入 `data_candidates.tsv` 前检查：

1. 来源论文和accession是否对应；
2. 受试者数而不是细胞数、spot数或切片数；
3. 组织和疾病场景是否符合需求；
4. 必需metadata是否存在；
5. 原始或处理后文件是否实际公开；
6. 下载体量和计算负担是否可接受；
7. 是否可能与其他候选共享患者。

不要把论文摘要中的样本量直接当作可分析患者数。

## 最小文件验证

数据只能按以下状态逐步升级：

- `not_checked`：只有引用或链接；
- `metadata_checked`：已检查样本表和文件清单；
- `sample_parsed`：已下载并用代码解析代表性文件；
- `downloaded`：路线需要的文件已取得；
- `checksum_verified`：文件完整性已记录；
- `blocked`：访问或文件结构阻断。

路线选择至少要求每个必需数据需求有一个 `decision=use` 且达到 `sample_parsed` 的候选。
此外，`subjects`只填写整数形式的独立生物学单位数量；它必须达到
`minimum_subjects`。候选的疾病、组织、模态和生物学单位必须与需求合同一致，
`fields_checked`必须覆盖全部`required_fields`，才能把`contract_match`设为`true`。
原始列名与合同字段的对应关系写入notes或解析产物，不能只勾选“已检查”。

### 候选队列不等于一个文件

`data_candidates.tsv`记录可分析队列，`data_resources.tsv`记录真正被读取的
文件或快照。一个队列的表达、临床结局、平台注释和样本映射可能来自不同来源，
因此每个资源必须分别记录：

- URL、版本或Last-Modified、访问日期、本地文件名、字节数和checksum；
- 它实际提供哪些必需字段；
- 用于跨来源连接的标识符及原始列名；
- 代表性解析状态。

必需字段必须被资源行的`fields_supplied`并集完全覆盖。网页声称“含临床数据”
不能替代对实际下载文件的字段检查。若来源会原地更新，checksum变化必须使运行
失败并触发重新审计，不能静默接受新文件。

跨来源拼接至少检查ID唯一性、集合覆盖、未匹配数、重复数、字段类型、单位和结局
编码。仅仅得到相同行数不是身份验证。

代表性解析必须保存：

- 下载URI和日期；
- 文件名、大小和checksum（稳定时）；
- 解析命令；
- 行列或对象维度；
- 关键字段检查；
- 失败信息。

公开可下载不自动等于允许重新分发。向公开Git仓库提交逐患者派生表前，还要记录原始
资源的许可证、署名要求和派生数据再分发条件；未完成该审查时，只提交生成代码、
manifest、汇总统计和不含逐患者记录的审计产物。

## 队列独立性

不同accession不代表独立。检查：

- 来源论文、作者和机构；
- 招募时间和地点；
- 患者或样本ID；
- 数据对象的上游来源；
- 论文是否重复使用公共队列。

需要外部验证时，`independence_required=true` 的需求只能由 `independence=independent` 的候选满足。

### 独立患者仍可能发生分析泄漏

`cohort_usage.tsv`按分析步骤登记同一队列是否影响了特征、模型参数或cutoff。
患者与训练队列不重叠，并不代表该队列仍可被称为外部验证：只要它曾参与结局筛选、
调参或cutoff选择，之后就只能标为开发、内部验证、敏感性或复现用途。校验器会阻止
同一`cohort_key`同时影响开发又被声明为`external_validation`。

## 停止或替换数据

以下情况不得靠猜测补字段：

- 中心比较或结局字段缺失；
- 访问审批无法在项目时间内获得；
- 患者身份和重叠无法解释；
- 只有细胞级数量，没有足够患者；
- 只有与训练队列重叠的验证数据。

允许更换数据、降低claim或停止路线，不允许臆造metadata。
