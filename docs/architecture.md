# Paper2Paper 最小架构

## 架构服务什么

架构只服务一个结果：从真实锚点文献形成目标论文。它要让初学者能够看懂并复核 AI 的判断，同时防止数据未取得、代码未运行、Figure 无来源或训练复现被误当成新论文。

## 两个循环

```text
主循环：锚点文献 → 候选目标论文 → 真实核验 → 正式论文
                       ↑                    │
                       └─ workflow 修复后复验 ┘
                              次循环
```

主循环产生论文；次循环只修复真实工作暴露的问题。次循环没有独立的“平台完成”目标。

## 两种研究 workspace

### Pilot

位置：`pilots/<id>/`

每个 Pilot 只对应一篇真实锚点文献，保存：

- 锚点特有框架和 Figure—证据映射；
- 硬伤、仍可利用部分和目标论文修复设计；
- 完整但不过度膨胀的候选路线；
- 数据、代码和近邻发表的真实预检；
- 最小真实运行、失败、结果和限制；
- 用户对继续、修改、保留训练或建立目标论文的决定；
- 执行中发现的 workflow 问题及修复后复验。

Pilot 可以停止，也可以只作为学习案例；它不自动成为论文。

### Manuscript project

位置：`manuscript-projects/<id>/`

只接收用户明确批准的候选路线，保存：

- 来源 Pilot、路线和关键真实运行；
- 冻结的队列、排除规则、统计单位、模型、参数和 Figure 合同；
- 正式运行、source tables、Figures、结果和限制；
- 稿件以及用户的最终发布决定。

正式项目必须重新执行分析。Pilot 的结果只支持“为什么值得建立项目”，不能直接冒充稿件结果。

## 支持代码不是研究层

`src/paper2paper/` 只提供：

- 初始化 Pilot；
- 校验表格、引用和阶段依赖；
- 显示状态与下一步；
- 在用户批准后建立独立 manuscript project。

`tests/` 只保护会导致错误数据、假运行、错误科学边界或越权建立稿件的关键行为。它们不构成论文证据，也不追求覆盖所有可能论文类型。

## 为什么只有轻量跨 Pilot 问题账，而没有中央平台层

Paper2Paper 不需要中央能力成熟度 registry、独立模块发布、路线评分或迁移史；这些机制不能直接产生目标论文。

但多个对话若只把发现留在各自 `issues.tsv`，其他对话无法知道问题已经发生、怎样处理、是否复验。因此仓库保留一个最小聚合层：

- `pilots/*/evidence/issues.tsv`：保存不可改写的现场事实和当前论文修复；
- `learning/findings.tsv`：保存已经归类的产品问题、来源、处理状态和复验引用；
- `reports/workflow-learning.md`：从全部 Pilot 和学习账生成的可读汇总。

原始候选不会自动成为产品缺口。只有真实发生、会影响论文判断、能形成有限补法的问题才改文档/代码/测试，并用来源 Pilot 复验。这个聚合层只服务次循环，不能延迟已经可以推进的主循环。

## 最小目录

```text
Paper2Paper/
├─ README.md
├─ RULES.md
├─ PROJECT_STATE.md
├─ src/paper2paper/
├─ tests/
├─ pilots/
├─ manuscript-projects/
├─ learning/              # 经过归类的跨 Pilot 产品发现
├─ reports/               # 可再生的跨 Pilot 学习报告
└─ docs/
```

目录和校验通过都不是科学完成。真实文件、真实运行、Figure/source table、科学审查和用户批准必须分别存在。
