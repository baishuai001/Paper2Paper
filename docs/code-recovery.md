# 代码寻找、组合与重建

锚点代码不可用不等于分析思路必须放弃。Paper2Paper把代码问题拆成模块解决，而不是要求找到一个能复现整篇论文的仓库。

## 先定义代码模块合同

每个Figure所需模块写入 `code_requirements.tsv`：

- 模块名称和论文作用；
- 输入格式；
- 输出格式；
- 是否必需；
- 最低测试；
- 科学不变量，例如患者级独立性、对比方向、无结局泄漏和稳定特征顺序。

模块合同不清楚时不能可靠比较donor代码。

## donor搜索顺序

按以下顺序搜索并记录检索式：

1. 锚点论文作者仓库和补充材料；
2. 锚点数据生成论文的预处理代码；
3. 方法作者或官方软件包文档；
4. 实现相同模块的高质量相关论文；
5. 通用工程模板；
6. 基于上述来源重建。

一个路线可以组合多个donor：锚点提供科学顺序，数据论文提供预处理，官方包提供统计实现，相关论文提供工程结构，AI补适配器和测试。

## 搜索和初筛

搜索词由模块、方法、数据类型、语言和可执行词组成，例如：

```text
<method/module> <single-cell/bulk/spatial> <R/Python> GitHub workflow script
```

候选写入 `code_candidates.tsv`，至少检查：

- 固定commit、tag或版本；
- 许可证和允许的复用范围；
- 语言、环境和系统依赖；
- 非交互入口；
- 输入输出是否匹配模块合同；
- 硬编码路径、全局状态和手工GUI步骤；
- 私有输入或作者本地对象；
- 安装和最小真实数据执行结果。

## 验证状态

- `not_checked`：只找到链接；
- `inspected`：已检查结构、版本、许可和入口；
- `install_passed`：目标环境安装成功；
- `smoke_passed`：代表性真实输入非交互运行成功；
- `tested`：模块和科学不变量测试通过；
- `blocked`：无法安装、许可不明或依赖不可得输入。

必需模块至少需要一个 `decision=use` 且达到 `smoke_passed` 的候选，才能支持路线选择。
该候选还必须把`contract_match`设为`true`，记录具体`smoke_input`、
`smoke_output`和`tests_passed`；`tests_passed`必须覆盖模块合同中的全部
`required_tests`。仅写“运行成功”或附一张图不能作为测试证据。

## 重建代码

重建不是凭记忆重写。执行顺序：

1. 固定科学公式、输入输出和预期方向；
2. 为每个关键步骤找到方法或代码依据；
3. 建立最小合成fixture和一个真实小样本；
4. 编写非交互函数和命令行入口；
5. 增加单元测试；
6. 增加真实数据smoke test；
7. 增加从manifest到source table的集成测试；
8. 增加患者独立性、无泄漏、ID匹配、方向和行数等科学不变量；
9. 记录环境、随机种子和参数；
10. 将来源类型标记为 `reconstructed`。

只有通过同样测试的重建代码才能与外部可靠donor等价使用。

## 何时不应继续重建

- 无法确定核心统计量或算法；
- 关键输入依赖不可取得的私有对象；
- 许可不允许复用；
- 预计重建负担超过路线的论文价值；
- 没有可用于验收的真实或合成fixture；
- 该模块只服务于可删除的装饰性图件。

此时应删除非必要模块、换donor、降低claim、选择其他路线或停止，而不是无限补代码。
