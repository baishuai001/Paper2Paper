# 跨论文模块复用

## 模块复用解决什么问题

真实文献常出现以下组合：

- 锚点文献的科学思路和 Figure 顺序很好，但没有代码或代码质量差；
- 某篇代码供体文献对其中一个分析步骤给出了高质量实现；
- 方法论文或官方包提供了更可靠的统计计算；
- 数据论文提供了原始数据解析细节；
- Paper2Paper 需要补齐接口、测试和目标环境适配。

正确做法不是复制代码供体文献的整套 pipeline，也不是凭记忆重写锚点分析，而是把锚点文献所需的能力拆成有合同的模块，再为每个模块选择和组合 donor，服务最终目标论文。

## 什么才是 Module

一个 Module 必须是可独立说明和测试的分析能力，例如：

- 从平台注释和表达矩阵生成锁定 signature 的患者级分数；
- 对单细胞髓系子集进行患者级 pseudobulk 差异分析；
- 在空间对象中计算预先定义的细胞状态共定位；
- 从生存 source table 生成 Cox、KM 和校准输出。

以下内容不是合格模块：

- “复现某某论文”的整个目录；
- 只有一段 notebook、没有输入输出合同的代码；
- 只在作者私有对象上运行的脚本；
- 许可证未知或入口必须手工点击的仓库；
- 仅凭一张看似合理的图声称可复用的函数。

## 模块合同

每个模块至少冻结以下内容。

### 身份与来源

- `module_id`、名称、版本和对应 `capability_id`；
- 科学思路来源；
- 实现 donor、版本/commit 和许可证；
- Paper2Paper 新增或修改的部分；
- 维护者和审查日期。

### 输入合同

- 文件/对象格式和必需字段；
- 模态、平台、物种、疾病限制；
- 患者、样本、细胞、spot 等生物学与统计单位；
- 预处理尺度、基因/探针 ID、批次和缺失规则；
- 数据身份连接和最小样本要求；
- 是否允许私有、受控或动态外部输入。

### 输出合同

- source table 的行、列和唯一键；
- Figure 或模型对象；
- 估计量、不确定性和检验；
- 日志、manifest、版本和失败状态；
- 输出能够支持和不能支持的 claim。

### 科学不变量

- 患者级 claim 不使用细胞伪重复；
- 比较方向和事件编码不反转；
- discovery/validation 没有未声明泄漏；
- 输入行数、ID 集合和输出行数一致；
- 特征顺序、系数、映射和 cutoff 可重算；
- 随机过程有种子或稳定性范围；
- 多重检验、协变量和缺失策略与合同一致。

### 失败合同

模块必须说明何时 fail closed，例如：

- checksum、字段或 ID 不匹配；
- 必需基因缺失超过阈值；
- 患者数不足；
- 输入尺度无法识别；
- 统计模型不收敛；
- 外部服务版本或响应无法保存。

不能通过猜测 metadata、静默删除样本或自动改 cutoff 让运行“成功”。

## Donor 搜索与组合顺序

按模块而不是整篇论文搜索：

1. 锚点作者代码和补充材料；
2. 锚点数据生成论文的预处理代码；
3. 方法作者或官方软件包；
4. 实现相同模块的高质量相关论文；
5. 有明确许可和测试的通用工程实现；
6. 基于上述证据独立重建。

一个模块可以组合多个 donor。例如：

- 锚点论文确定科学顺序和输出角色；
- 数据论文确定原始对象解析；
- 官方包负责统计模型；
- 相关论文提供非交互执行结构；
- Paper2Paper 编写适配器、manifest 和测试。

记录必须分别说明每个来源贡献了什么，避免将“受启发”“复制代码”和“方法依据”混为一谈。

## 复用前的兼容性审查

即使模块在一个 Pilot 中真实运行过，另一个项目使用前仍要逐项检查：

| 项目 | 必问问题 |
| --- | --- |
| 模态与平台 | 输入是 counts、TPM、log 表达、微阵列 probe、单细胞对象还是空间矩阵？ |
| 生物学单位 | donor、患者、样本、细胞和 spot 是否与原模块一致？ |
| 数据尺度 | 归一化、批次处理和参考分布是否兼容？ |
| 特征映射 | 基因 ID、物种、探针和重复特征如何处理？ |
| 比较与结局 | 方向、时间起点、事件编码和响应定义是否一致？ |
| 统计假设 | 独立性、样本量、协变量和模型条件是否满足？ |
| 输出与 claim | 新项目需要的 Figure/claim 是否超出模块输出能力？ |
| 环境与许可 | 目标 OS、权限、依赖和复用范围是否允许？ |

审查结果只能是：

- `compatible`：合同匹配，可进入目标环境 smoke test；
- `adapter_required`：科学合同相同，但需要明确格式/平台适配；
- `claim_downgrade`：能运行但只能支持更低证据层级；
- `incompatible`：拒绝复用并寻找其他 donor 或重建。

“同样叫生存分析”“都使用 Seurat”不构成兼容证据。

## 测试层级和成熟度

### 测试层级

1. **结构/静态检查**：入口、依赖、许可和合同字段完整；
2. **单元测试**：关键公式、映射、事件编码和失败条件；
3. **合成集成测试**：从 manifest 到 source table/Figure 的小闭环；
4. **真实参考案例**：在来源 Pilot 的真实数据和目标环境运行；
5. **独立迁移案例**：在第二篇兼容文献中运行并检查科学不变量；
6. **科学审查**：确认结果解释没有超过统计和数据边界。

这些证据分开登记。单元测试通过不等于真实迁移通过；真实输出方向相同也不等于像素级复现或临床有效。

### Module release 成熟度

- `draft`：合同或实现仍在形成，不能作为可靠 donor；
- `unit_verified`：至少一个合格单元案例通过，但尚无真实数据参考证据；
- `reference_verified`：来源 Pilot 的真实数据参考案例通过，且 oracle 不是由同一冻结输出循环确认；
- `transfer_verified`：不同 Pilot、锚点和数据集的独立真实迁移案例通过。

模块是否继续使用另由 `active/blocked/deprecated` lifecycle 表达。Promotion 则使用 `observed/provisional/confirmed/rejected/deprecated`；不要把 promotion 的证据成熟度与 module release 的测试成熟度混用。

模块版本升级不能静默改变输入尺度、统计单位、公式或输出含义。此类变化属于破坏性版本，并触发受影响回归案例。

每个 release 还必须把 `entrypoint`、`environment_lock`、`contract_path`
和 `unit_test_path` 四项文件的 SHA256 写入 `module_releases.tsv`。任一文件内容
发生变化而版本号和 release 记录未更新时，registry 校验必须失败。这样可以避免
“登记表仍显示已验证，实际代码、依赖、合同或测试已经悄悄变化”的陈旧证据。

这四项都是文本资产，hash 计算前统一把 CRLF/CR 行尾规范化为 LF；因此 Windows
和 Linux checkout 得到相同的 release 内容身份。`runs.tsv.commit` 和运行 metadata
仍保存实际执行文件的原始字节 hash，两者用途不同，不能相互替代。

## 数据解析器与外部服务

数据资源本身仍留在各 Pilot/正式项目中；可以复用的是有合同的解析器或资源适配器。适配器必须保留：

- 数据库、accession/URI、版本或访问日期；
- 文件名、bytes、checksum；
- 字段和 ID 映射；
- 原始到分析对象的转换；
- 许可、署名和派生数据再分发边界；
- 资源更新后的 fail-closed 行为。

TIDE、SubMap、在线富集、知识网络等动态服务必须保存请求参数、访问日期、服务/数据库版本、响应文件及 checksum。无法保存时降低可复现等级和 claim ceiling。

## 模块失败如何反馈论文

模块失败不自动意味着整条论文路线失败。按顺序判断：

1. 输入不兼容，是否存在有限适配；
2. donor 不可靠，是否有官方/相关论文替代；
3. 非中心 Figure，是否可以删除；
4. 只影响 claim 强度，是否可以降低主张；
5. 中心证据无法生成，是否 reroute 或 stop。

预计重建成本超过论文价值、缺少可验证输入、核心算法无法确定或许可不允许复用时，应停止模块工程，而不是无限补代码。

## 一个具体复用例子

若锚点文献需要“单细胞状态 → bulk 外部支撑 → 生存结果”的证据顺序，但作者代码缺失，而目标是形成目标论文：

- 锚点文献继续作为科学问题和 Figure 顺序来源；
- 从代码供体文献采用经审计的单细胞状态评分模块；
- 从官方包采用患者级生存统计实现；
- 从数据/方法供体文献借鉴跨平台基因映射细节；
- Paper2Paper 为目标数据编写适配器、患者级不变量和真实 smoke test。

只有三个模块在目标数据合同中分别通过后，才能组合成目标论文的路线。不能因为代码供体文献的实现质量高，就把它的疾病假设、cutoff 或预期结果一起复制到目标论文。
