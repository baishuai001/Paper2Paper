# 最小执行、完整分析与稿件

## 最小执行试验

选择路线前必须完成一次小而真实的闭环：

1. 每个必需数据需求至少解析一个代表性文件；
2. 每个必需代码模块安装并运行真实小输入；
3. 所有最低主图映射到数据需求和代码模块；
4. 至少生成一个代表性source table或Figure片段；
5. 保存命令、环境、日志和失败；
6. 完成最近发表检索。

失败的安装、下载、解析、字段连接、统计和绘图同样写入`runs.tsv`或
`issues.tsv`。修复后新增运行，不能用成功输出覆盖失败证据。问题必须区分锚点缺陷、
当前实例缺陷和可推广的产品缺口；只有后者才修改Paper2Paper核心。

最小试验的目的不是提前完成论文，而是尽早发现访问、metadata、代码接口和统计单位问题。

执行可行性与稿件资格是两件事。`training`只表示某一类分析模块的学习或重建实例，
不表示整个workflow、其他模态或其他锚点论文已经被验证；`supporting`分析用于支撑另一条
主线。二者都可以达到`execution_ready`，但不能仅凭运行成功升级为最终稿件路线。只有
`manuscript_candidate`在通过科学、数据、代码、Figure和发表重合审查后才能成为
`manuscript_eligible`并进入选择。

运行或问题状态也必须说明解决范围：`resolved_in_pilot`只表示当前实例处理完成，
`partially_resolved_in_core`表示核心只有部分约束，`verified_in_core`才表示通用规则已有
相应校验和回归测试。

## 路线选择包

AI提交给用户的选择包必须包括：

- 每条路线的一句话问题；
- 路线用途：稿件候选、训练复现或辅助分析；
- 保留和改变的轴；
- 数据、代码、初学者负担和预计日历时间；
- 可用和缺失的数据；
- 已运行和待重建的代码模块；
- 最低主图；
- 最大风险、停止条件和初学者负担；
- 最近发表和可区分点；
- 代表性执行产物。

不得只给“推荐路线”和一段理由。

## 分析规范

`analysis/specification.md`至少冻结：

- 队列和排除标准；
- 患者、样本、细胞或spot等统计单位；
- 暴露、比较、结局和协变量；
- 预处理、批次处理和缺失值；
- 主要、验证、敏感性和探索性分析；
- 模型、参数、随机种子和软件版本；
- signature完整公式；
- Figure和source table输出；
- 可推翻中心claim的结果。

## 完整执行

每次运行写入 `runs.tsv`。任何改变输入、关键参数、代码commit或数据manifest的执行都应有新run ID。

成功运行必须能从记录中找到：

- 命令；
- commit；
- 环境；
- data manifest；
- 日志；
- artifact位置；
- 开始和结束时间。

## 结果反馈

结果写入 `results.tsv`，包括：

- 可复查摘要；
- 支持、削弱、矛盾或不确定；
- 下一步continue、refine、reroute或stop；
- 局限；
- source table。

结果后新增的分析默认标记为探索性。不得通过不断改cutoff、终点、队列或marker追求阳性结果。

## 稿件生成

稿件内容必须来自已验证事实：

- Methods来自冻结规范和运行记录；
- Results来自source table；
- Figure legend写清统计单位和检验；
- Discussion区分结果、解释和推测；
- Limitations包含数据缺失、队列偏倚、代码重建和证据层级；
- 标题和摘要不超过claim ceiling。

平台工程在这里停止。除非真实稿件暴露新的阻断问题，不再为通用化本身扩建工具。
